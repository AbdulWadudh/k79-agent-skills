## Changes

### Changed

#### Use an agent-agnostic install command and document updates

**Scope:** changelog.config.json, README.md, skills/k79-master-engineering

#### Why

The install line named OpenCode and Claude Code. Anyone using another agent had to edit the
command before it worked, and the release notes repeated the same limitation. The update path
was also implicit: it was not clear whether re-running `add` or running `update` was required.

#### What

- Changed the canonical install command to
  `bunx skills@latest add AbdulWadudh/k79-agent-skills -g --agent '*' -y`.
- Added the per-agent form (`-a opencode`, `-a claude-code`) and the `--all` shorthand as
  optional alternatives, not the default.
- Documented that re-running `add` updates in place because it reads the latest default branch,
  and kept `skills update -g -y` as the hash-based alternative.
- Updated the bootstrap prompt, Phase 0, the router, and the release-note config so every copy
  of the command matches.

#### Verification

- `bun run validate` passes.
- `bun run changelog:check` passes.
- Generated release notes show the agent-agnostic command and the update guidance.

#### Notes

`skills add` follows the default branch, not a tag. The installed `VERSION` still tells you
which release the files correspond to.

### Fixed

#### Ship the OpenCode reminder as plain JavaScript

**Scope:** skills/k79-master-engineering/hooks/

#### Why

The OpenCode reminder was shipped as `.ts`. Without `@types/node` in the config folder, editors
reported `TS2591` for every `node:` import and `TS7006` for the two implicit-any parameters.
Installing type packages into `~/.config/opencode` just to satisfy a 25-line plugin is the wrong
trade.

#### What

- Renamed `opencode-reminder.ts` to `opencode-reminder.js`; OpenCode loads both.
- Updated the hook README and replaced the installed plugin.
- Kept the plugin behavior identical: push the reminder into the compaction context.

#### Verification

- `bun -e "import('file:///.../k79-reminder.js')"` resolves and exports `K79Reminder`.
- OpenCode loads the plugin from `~/.config/opencode/plugins/`.
- No TypeScript diagnostics apply to a `.js` file.

#### Notes

If you prefer TypeScript, add `@types/node` and `@opencode-ai/plugin` to the config folder, then
type the parameters as `unknown` and `{ context: string[] }`.

## Installation

```bash
bunx skills@latest add AbdulWadudh/k79-agent-skills -g --agent '*' -y
```

`--agent '*'` installs for every supported agent. To target one agent, use `-a opencode` or `-a claude-code`. Use `npx skills@latest add ...` when Bun is unavailable, and append `--copy` on Windows if linking fails.

## Updating

Re-run the install command to update. `skills add` reads the latest default branch, so a separate update step is optional. For a hash-based refresh, run `bunx skills@latest update -g -y` (all global skills) or pass the eight `k79-*` names to update only the suite.
