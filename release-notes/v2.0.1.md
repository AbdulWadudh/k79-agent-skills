## Changed

### Run release-note validation from the skill validator

**Scope:** scripts/validate-skills.mjs

#### Why

After removing the aggregate changelog, `validate-skills.mjs` no longer checked any changelog
artifact. Release-note validation only ran as a separate CI step, so a local `bun run validate`
could pass with a broken manifest.

#### What

- `validate-skills.mjs` now invokes `release-notes.mjs --check` after the skill checks.
- CI keeps the explicit `release-notes:check` step; the two are intentionally idempotent.
- The release command therefore validates the manifest and entry diff before stamping.

#### Verification

- `bun run validate` prints the release-notes check and the skill count.
- A broken entry or a modified released entry makes `bun run validate` fail.
- `bun run release-notes:check` still passes independently.

#### Notes

Projects that copy only `release-notes.mjs` are unaffected; `validate-skills.mjs` is a suite
maintainer script.

## Verification

- `bun run validate` — skill names, frontmatter, references, and version markers.
- `bun run release-notes:check` — entry schema, append-only history, and the release-note manifest.
- `bun run agents:check` — the `AGENTS.md` router block matches `AGENTS.router.md`.

## Installation

```bash
bunx skills@latest add AbdulWadudh/k79-agent-skills -y
```

Default: project-local. Creates `.agents/skills/` and `skills-lock.json`; no agent selection and no per-agent mirrors. Advanced: add `-g` for `~/.agents/skills/`, or `-a <agent>` / `--agent '*'` for mirrors.

## Updating

Re-run the install command for the scope you use. `skills add` reads the latest default branch, so a separate update step is optional. For a hash-based refresh, run `bunx skills@latest update -y` (current scope) or `-g -y` / `-p -y`.
