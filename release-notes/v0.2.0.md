## Changes

### Added

#### Add a folder-per-change changelog ledger with generated release notes

**Scope:** changelog/, scripts/changelog.mjs, scripts/release.mjs, CHANGELOG.md

#### Why

A single hand-maintained `CHANGELOG.md` causes merge conflicts on concurrent branches, loses
entries when the Unreleased section is reset, and forces the release notes to be re-written
from commit subjects that say nothing about why a change exists.

#### What

- Added `changelog/YYYY/MM/YYYY-MM-DD-<slug>.md` as the atomic record, with frontmatter for
  `title`, `date`, `type`, `scope`, `version`, `released`, and `breaking`.
- Added `scripts/changelog.mjs` with four modes: validate and regenerate, `--check`,
  `--stamp <version>`, and `--release <version>`.
- `CHANGELOG.md` is now generated. `Unreleased` is derived from entries without a version, so
  nothing has to be reset or deleted at release time.
- `release-notes/vX.Y.Z.md` is generated from the same entries, including highlights, grouped
  change details, breaking changes, verification commands, and install/update instructions.
- `release.mjs` now stamps unreleased entries, regenerates both files, and refuses to release
  when there is nothing to record.
- CI runs `bun run changelog:check` so a stale or malformed changelog fails the build.

#### Verification

- `bun run changelog:check` passes.
- Generated `CHANGELOG.md` reproduces the `0.1.0` history from its backfilled entry.
- `bun run release --dry-run` reports the entries that would be stamped.

#### Notes

Existing release notes are never overwritten; pass `--force` to regenerate one deliberately.

#### Teach the Git skill to maintain changelogs and release notes

**Scope:** skills/k79-logging-errors-git/SKILL.md

#### Why

Agents write commit messages but rarely maintain the artifacts a release needs. Without a rule,
changelogs become a single conflicted file, release notes are generated from uninformative
commit subjects, and past entries are rewritten until they no longer describe what shipped.

#### What

- Added a changelog and release-notes section to `k79-logging-errors-git` covering the folder
  layout, the entry schema, the write rules, the release sequence, and the anti-patterns.
- The rules make one file per logical change mandatory, forbid editing a stamped entry, and
  require `CHANGELOG.md` and release notes to be generated from the entries.
- Added the changelog trigger to the router and to Phase 4 of the master orchestrator.

#### Verification

- `bun run validate` passes with the updated description and metadata.
- The new section references the same schema that `scripts/changelog.mjs` validates.

#### Notes

This is an instruction, not a generator. Projects without tooling are told to create the
generator first so the changelog has one source of truth.

### Changed

#### Make the skill router portable across agents

**Scope:** skills/k79-master-engineering/AGENTS.router.md, README.md

#### Why

The router named skills as relative paths (`k79-spec-driven/SKILL.md`), which do not resolve
from a project root, and it assumed a single skills directory. Agents without a skill loader
fell back to a file read that could not succeed.

`AGENTS.md` is also not universal: Claude Code ignores it when a project `CLAUDE.md` exists,
Gemini CLI reads `GEMINI.md` by default, Aider reads `CONVENTIONS.md`, and Copilot's repo-wide
chat still prefers `.github/copilot-instructions.md`.

#### What

- The router now resolves skills by name first, with an ordered list of absolute fallback
  roots: `<project>/.agents/skills`, `~/.agents/skills`, `~/.claude/skills`,
  `~/.config/opencode/skills`.
- Added a changelog trigger to the router and the master orchestrator.
- Added an agent compatibility table to the README covering OpenCode, Claude Code, Codex,
  Cursor, Windsurf, Cline, Copilot, Gemini CLI, and Aider.
- The bootstrap prompt now writes thin shims (`CLAUDE.md` with `@AGENTS.md`, `GEMINI.md`,
  `.github/copilot-instructions.md`, `.aider.conf.yml`) instead of duplicating the router
  body, and preserves every existing project-specific instruction.
- The router states plainly that instruction files are context, not enforcement.

#### Verification

- `bun run validate` passes.
- Router paths checked against the installed global layout on Windows.
- Claude Code 2.1.316 confirmed to support direct `AGENTS.md` reads.

#### Notes

Hard enforcement still needs hooks or CI. A markdown file marked `MANDATORY` remains a prompt.

## Installation

```bash
bunx skills@latest add AbdulWadudh/k79-agent-skills -g -a opencode -a claude-code -y
```

Use `npx skills@latest add ...` when Bun is unavailable, and append `--copy` on Windows if linking fails.

## Updating

Tell your agent: `update k79-agent-skills`. It compares the installed version with this release and waits for approval before updating.
