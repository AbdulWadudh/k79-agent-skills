## Changes

### Changed

#### Make project-local install the default and drop agent selection

**Scope:** README.md, changelog.config.json, skills/k79-conductor

#### Why

The default install required `--agent '*'`, which selected every supported agent and created
per-agent mirrors the user never asked for: `.claude/skills/`, `agent/skills/`, and
`skills-lock.json`. The intent was a local copy in `<repo>/.agents/skills/`, not a machine-wide
or every-agent installation.

#### What

- The documented default is now `bunx skills@latest add AbdulWadudh/k79-agent-skills -y`.
- It creates exactly `.agents/skills/` and `skills-lock.json`; no `.claude/skills/`, no
  `agent/skills/`, and no agent-selection prompt.
- Global (`-g`) and per-agent (`-a <agent>` / `--agent '*'`) installs moved to an advanced
  section with the exact output of each.
- The bootstrap prompt installs project-local and never asks the user to choose agents.
- The update protocol reinstalls the same scope with `-y` or `-g`, not `--agent '*'`.
- The release-note install block shows the local command first.

#### Verification

- Fresh temp project: `add ... -y` produced only `.agents/skills/` and `skills-lock.json`.
- Fresh temp project: `add ... --agent '*' -y` produced `.agents/skills/`, `.claude/skills/`,
  `agent/skills/`, and `skills-lock.json`.
- `bun run validate` and `bun run changelog:check` pass.

#### Notes

Existing global installs keep working. They are no longer the documented default.

#### Remove duplicated routing from AGENTS.md and add a sync check

**Scope:** AGENTS.md, skills/k79-conductor, scripts/sync-agents.mjs, README.md

#### Why

The generated `AGENTS.md` contained the same seven task-to-skill mappings twice: once in
`K79.reminder.md` and again in `AGENTS.router.md`. It was also unclear whether
`AGENTS.router.md` was read at runtime. The manual "re-sync this block" instruction had no way
to prove the block still matched.

#### What

- `K79.reminder.md` is now the only routing list in `AGENTS.md`.
- The router block's seven-item trigger list is replaced with one line: load `k79-conductor`
  first; it owns phase order and routes to the seven domain skills.
- The router block is wrapped in `<!-- k79:router:start -->` and `<!-- k79:router:end -->`.
- Added `sync-agents.mjs`: `--check` fails on drift, `--sync` replaces only the marked block.
- Added `agents:check` and `agents:sync` scripts, a CI step, and a pre-release check.
- Added an artifact-role table to the README. `AGENTS.router.md` is documented as the canonical
  template, not a shim and not read at runtime.
- Added a dogfooded `AGENTS.md` at the repo root with the reminder, marked block, and project
  context.

#### Verification

- `bun run agents:check` passes.
- Editing one line inside the block makes `--check` fail with the first differing line.
- `--sync` restores the block and preserves the Project Context section outside the markers.
- `bun run validate` and `bun run changelog:check` pass.

#### Migration

Existing projects keep working with the old block. To adopt the new format, re-run the
bootstrap prompt or add the markers manually, replace the block with
`k79-conductor/AGENTS.router.md`, remove the duplicate trigger list, then run
`node scripts/sync-agents.mjs --check`.

#### Notes

`AGENTS.router.md` is still required. Do not delete it: it is the source the sync script reads.

## Installation

```bash
bunx skills@latest add AbdulWadudh/k79-agent-skills -y
```

Default: project-local. Creates `.agents/skills/` and `skills-lock.json`; no agent selection and no per-agent mirrors. Advanced: add `-g` for `~/.agents/skills/`, or `-a <agent>` / `--agent '*'` for mirrors.

## Updating

Re-run the install command for the scope you use. `skills add` reads the latest default branch, so a separate update step is optional. For a hash-based refresh, run `bunx skills@latest update -y` (current scope) or `-g -y` / `-p -y`.
