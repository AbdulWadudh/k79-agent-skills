## Changes

### Added

#### Ship the changelog generator with the skill so other projects can adopt it

**Scope:** skills/k79-logging-errors-git/scripts/changelog.mjs, changelog.config.json, README.md

#### Why

The changelog rules were installed globally, but the generator was not: only `SKILL.md` reached
other projects. Agents were told to "create a generator" with no reference implementation, and
this repository's script hard-coded its own GitHub URL and skill count.

#### What

- Moved the canonical generator into `k79-logging-errors-git/scripts/changelog.mjs`, so the
  `skills` CLI installs it with the skill.
- Made it project-agnostic: repository URL comes from `changelog.config.json` or the `origin`
  remote, license and verification come from config, and install/update sections are omitted
  when not configured.
- Added `--init`, which creates `changelog/`, `changelog/TEMPLATE.md`, `CHANGELOG.md`, and
  `release-notes/` in any repository.
- Kept `scripts/changelog.mjs` in this repository as a thin wrapper over the skill copy, so the
  two cannot drift.
- The bootstrap prompt now copies the generator into a project and wires the package scripts.

#### Verification

- Fresh temp repository: `--init`, add one entry, generate, stamp, and release all succeed.
- This repository: `bun run changelog:check` and `node scripts/changelog.mjs --check` pass.
- `changelog.config.json` supplies this repo's install and update text.

#### Notes

The generator is dependency-free and works under Node 22+ or Bun. It does not publish a package.

### Changed

#### Trim the suite update protocol to its essentials

**Scope:** skills/k79-master-engineering/SKILL.md, skills/k79-master-engineering/AGENTS.router.md

#### Why

Phase 0 spent fourteen lines on one operation. It listed three fallback lookups, per-agent
install variations, an alternative update command, and a re-sync instruction. The router
repeated the same protocol, so an agent read it twice and could follow two different versions.

#### What

- Reduced Phase 0 to six bullets: current, latest, same, newer, approval, never.
- Kept one fallback lookup and moved install variations into one parenthetical.
- Reduced the router's update block to four bullets and let it point at the release, not at a
  duplicated command sequence.
- Replaced the remaining `k79-*/SKILL.md` path references in the master skill with skill names,
  and validation now checks every backticked `k79-*` name instead of only file paths.

#### Verification

- `bun run validate` passes.
- The router and Phase 0 describe the same approval gate and reinstall command.

#### Notes

The README still holds the long-form user documentation, which is the right place for install
variants and manual commands.

### Fixed

#### Remove the duplicate release title from generated notes

**Scope:** scripts/changelog.mjs, release-notes/

#### Why

GitHub renders the release title above the body. The generated body also started with
`# <project> v<version>`, so every release page showed the same heading twice.

#### What

- The generator no longer writes an H1 into `release-notes/vX.Y.Z.md`; the body starts with
  release metadata.
- Removed the duplicate H1 from the existing `v0.1.0` and `v0.2.0` notes and refreshed both
  published release bodies.

#### Verification

- Generated `release-notes/v0.2.0.md` starts with `**Release date:**`.
- `gh release view v0.2.0` shows one title and no repeated heading.

#### Notes

The release title remains owned by the workflow (`--title "k79-agent-skills vX.Y.Z"`), so the
body is safe to read standalone as well.

## Installation

```bash

```

Use `npx skills@latest add ...` when Bun is unavailable, and append `--copy` on Windows if linking fails.
