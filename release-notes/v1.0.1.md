## Changes

### Fixed

#### Keep the old skill path as a reminder fallback

**Scope:** skills/k79-conductor/hooks/

#### Why

The 1.0.0 rename note promised that the reminder hooks would still find an in-progress install
under the old path. The shipped hook lookup only used `k79-conductor`, so the promise was not
kept.

#### What

- The Claude Code reminder now checks `k79-conductor` first, then `k79-master-engineering`.
- The OpenCode compaction plugin checks the same two paths.
- The fallback is temporary; it can be removed after the migration window.

#### Verification

- `node skills/k79-conductor/hooks/k79-reminder.mjs` prints the reminder.
- Removing the conductor directory still resolves through the fallback.
- `bun run validate` and `bun run changelog:check` pass.

#### Notes

The fallback does not install anything. It only helps a session whose skill directory is being
replaced during the 1.0.0 migration.

## Verification

- `bun run validate` — skill names, frontmatter, references, and version markers.
- `bun run changelog:check` — entry schema and generated changelog freshness.

## Installation

```bash
# Project (from the repo root)
bunx skills@latest add AbdulWadudh/k79-agent-skills --agent '*' -y

# Global
bunx skills@latest add AbdulWadudh/k79-agent-skills -g --agent '*' -y
```

Pick one; neither is the default. Project scope pins the suite to the repo and can be committed. `--agent '*'` installs for every supported agent; narrow with `-a opencode`. Use `npx` when Bun is unavailable, and `--copy` on Windows if linking fails.

## Updating

Re-run the install command for the scope you chose. `skills add` reads the latest default branch, so a separate update step is optional. For a hash-based refresh, run `bunx skills@latest update -g -y` (global) or `-p -y` (project).
