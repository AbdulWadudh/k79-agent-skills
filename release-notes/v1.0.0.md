## Changes

### Changed

#### Make the bootstrap install explicitly agent-agnostic

**Scope:** README.md, release-notes/v0.4.0.md

#### Why

The bootstrap prompt and the v0.4.0 release notes still read as if the suite targets OpenCode
and Claude Code. The install command was agent-agnostic, but the surrounding text was not, and
the optional reminder hooks looked like a two-agent target list.

#### What

- Added the `--agent '*'` explanation, the per-agent narrowing examples, and the update note to
  the bootstrap prompt.
- Clarified that `AGENTS.md` covers every agent and the hooks are an optional extra for harnesses
  with hook APIs.
- Refreshed the v0.4.0 release notes from the current config so the published page shows the
  same command.

#### Verification

- The bootstrap block, install section, and release notes all show
  `bunx skills@latest add AbdulWadudh/k79-agent-skills -g --agent '*' -y`.
- `bun run validate` and `bun run changelog:check` pass.

#### Notes

Documentation only. No skill file changed, so no new suite version is required.

#### Ask for install scope instead of defaulting to global

**Scope:** README.md, skills/k79-conductor, changelog.config.json

#### Why

The setup only showed a global install. Global is wrong when a repository needs a pinned,
reproducible version that teammates and CI share, and it silently changes every project on the
machine at once. Project scope already existed but was presented as an afterthought.

#### What

- The bootstrap prompt now asks for global or project scope and refuses to install before the
  answer.
- The README presents both scopes as equals, with the trade-offs and the commands side by side.
- Phase 0 and the router detect the installed scope (project first, then global) and update the
  same one.
- The release-note install block shows both commands; the update block points at the chosen
  scope.
- Project installs leave `~/.agents/skills/` untouched and can be committed.

#### Verification

- `bun run validate` passes.
- `bun run changelog:check` passes.
- The bootstrap block contains both commands and the "ask before installing" line.

#### Notes

When both scopes exist, the project copy wins because it is first in the router's resolution
order.

#### Rename the orchestrator to k79-conductor

**Scope:** skills/, scripts/, README.md

#### Why

"Master" implies ownership and carries a hierarchy the skill does not have. The skill coordinates
the domain skills; it does not own the work or the user.

#### What

- Renamed `skills/k79-master-engineering` to `skills/k79-conductor`.
- Updated the frontmatter name, title, description, Phase 0, router, reminder paths, README,
  validation script, release script, and hook paths.
- Kept the old skill directory in the hook lookup as a fallback so an in-progress install still
  finds the reminder.
- Added the conductor name to the skill-resolution order everywhere.

#### Migration

Remove the old skill, install the new suite, then re-run the project bootstrap so `AGENTS.md`
points at `k79-conductor`.

```bash
# Global
bunx skills@latest remove k79-master-engineering -g -y
bunx skills@latest add AbdulWadudh/k79-agent-skills -g --agent '*' -y

# Project (from the repo root)
bunx skills@latest remove k79-master-engineering -y
bunx skills@latest add AbdulWadudh/k79-agent-skills --agent '*' -y
```

The old name remains only in historical changelog and release-note files. Do not rewrite those;
they record what shipped at the time.

#### Verification

- `bun run validate` passes with 8 skills, all frontmatter names matching their directories.
- `bun run changelog:check` passes.
- `bunx skills@latest add AbdulWadudh/k79-agent-skills --list` lists `k79-conductor`.
- After migrating, `VERSION` is `1.0.0` and the old directory is gone.

#### Notes

This is the 1.0.0 release because the skill identifier changes. Installed copies are not
auto-migrated: the old name has to be removed once.

## Installation

```bash
# Project (from the repo root)
bunx skills@latest add AbdulWadudh/k79-agent-skills --agent '*' -y

# Global
bunx skills@latest add AbdulWadudh/k79-agent-skills -g --agent '*' -y
```

Pick one; neither is the default. Project scope pins the suite to the repo and can be committed. `--agent '*'` installs for every supported agent; narrow with `-a opencode`. Use `npx` when Bun is unavailable, and `--copy` on Windows if linking fails.

## Updating

Re-run the install command for the scope you chose. `skills add` reads the latest default branch, so a separate update step is optional. For a hash-based refresh, run `bunx skills@latest update -g -y` (global) or `-p -y` (project).
