# k79-agent-skills v0.1.0

**Release date:** 2026-11-03
**License:** MIT
**Skills:** 8 — 1 orchestrator + 7 domain skills

A modular, language-agnostic, Spec-Driven engineering skill suite for AI coding agents. It targets the failure modes that show up repeatedly in production codebases: hallucinated scope, God files, vague naming, circular imports, speculative overengineering, happy-path-only tests, swallowed errors, and bulk commits.

## Highlights

- **One orchestrator, seven focused skills.** `k79-master-engineering` routes work through Spec → Code → Verify → Commit and loads only the domain skills the task needs.
- **Namespaced installs.** Every skill keeps the `k79-` prefix, so it cannot collide with other skills in global agent directories.
- **Works across agents.** Installs through the [`skills`](https://github.com/vercel-labs/skills) CLI into OpenCode, Claude Code, Cursor, Cline, Windsurf, Codex, and other supported agents.
- **Approval-gated updates.** Saying “update k79-agent-skills” compares the installed version with the latest release, shows the changes, and stops for explicit approval before updating.
- **Version-aware releases.** `VERSION`, `metadata.version`, `package.json`, and the changelog are kept in sync by the release script.
- **Validated in CI.** Frontmatter, names, references, and version consistency are checked on every push and pull request.

## Installation

```bash
# OpenCode + Claude Code
bunx skills@latest add AbdulWadudh/k79-agent-skills -g -a opencode -a claude-code -y

# Node equivalent
npx skills@latest add AbdulWadudh/k79-agent-skills -g -a opencode -a claude-code -y
```

Install a single skill:

```bash
bunx skills@latest add AbdulWadudh/k79-agent-skills -g -s k79-spec-driven -a opencode -y
```

Install into the current project instead of globally: omit `-g`.

On Windows, append `--copy` if junction creation is blocked.

### Where files land

| Agent | Global path |
| :--- | :--- |
| OpenCode | `~/.agents/skills/` (read natively) |
| Claude Code | `~/.claude/skills/` (junction to `~/.agents/skills/`) |
| Other supported agents | Their own skills directory, linked to `~/.agents/skills/` |

## What's Included

| Skill | Problem it solves |
| :--- | :--- |
| `k79-master-engineering` | Skill sprawl and attention dilution. Routes tasks through four strict phases and owns the update protocol. |
| `k79-spec-driven` | Hallucinated scope and broken workarounds. Enforces a spec approval gate, blast-radius lock, spec scaling, and `@quirk` protection. |
| `k79-code-structure` | God files, directory bloat, bad naming, and circular imports. Enforces size caps, DAG imports, and strict naming rules. |
| `k79-evidence-and-simplicity` | Assumptions, overengineering, and debug loops. Requires proof, DRY extraction only on the Rule of 2+, YAGNI, and a 2-strike circuit breaker. |
| `k79-config-and-security` | Config drift and frontend secret leaks. Enforces the 3-tier config law, client/server isolation, scoped caches, and idempotency. |
| `k79-performance-and-db` | Slow queries, N+1 loops, and unbounded fetches. Enforces explicit columns, transactions, pagination, timeouts, and UI performance rules. |
| `k79-verification-testing` | False “done” claims and tautological tests. Mirrors `tests/`, bans mocks on pure helpers, and requires a 1:2 happy-to-breaking ratio. |
| `k79-logging-errors-git` | Swallowed errors, log spam, and sloppy commits. Enforces boundary logging with structured context and atomic commits with no AI attribution. |

## Updating

Tell your agent:

```text
update k79-agent-skills
```

It reads `~/.agents/skills/k79-master-engineering/VERSION`, checks the latest GitHub Release, shows the version delta and notes, and waits for approval.

Manual refresh of only the suite:

```bash
bunx skills@latest update k79-master-engineering k79-spec-driven k79-code-structure k79-evidence-and-simplicity k79-config-and-security k79-performance-and-db k79-verification-testing k79-logging-errors-git -g -y
```

## Changes

### Added

- Initial public release with the `k79-master-engineering` orchestrator and seven domain skills.
- MIT license.
- Global installation and agent linking via `npx skills add` / `bunx skills add`.
- Version markers (`VERSION` and `metadata.version`) so agents can compare installed and latest versions.
- Approval-gated self-update protocol triggered by “update k79-agent-skills”.
- Release automation: validation script, changelog generation, annotated tags, and GitHub Releases.
- `bun run skills` command that lists and counts the skills available in the repository.

### Fixed

- Skill frontmatter names now match their `k79-*` directories so global installs keep the `k79-` namespace and every router path resolves correctly.

### Verification

- `bun run validate` and `node scripts/validate-skills.mjs`: 8 skills validated at `0.1.0`.
- Global install tested on Windows: OpenCode reads `~/.agents/skills`; Claude Code receives junctions.
- Single-skill install tested with `-s k79-spec-driven`: only that folder is installed.
- Release flow tested end-to-end under Bun and Node: version bump, changelog entry, commit, annotated tag, and validation at the new version.

## Upgrade Notes

This is the first tagged release. If you installed an earlier untagged copy, the skill names were not namespaced (`spec-driven`, `code-structure`, …). Remove those before installing `0.1.0`:

```bash
bunx skills@latest remove spec-driven code-structure evidence-and-simplicity config-and-security performance-and-db verification-testing logging-errors-git -g -y
```
